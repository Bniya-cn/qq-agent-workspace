3. 检索缺少分类：llm_service.py::_load_local_character_refs 只遍历根目录并对子串匹配，再截取第一张。
   建议读取 catalog 建立内存索引：用户明确游戏 → 只查该游戏；未指定游戏 → 查角色所属游戏；跨游戏同名才询问。

   现检索器不认识新游戏目录下的 catalog，完成后必须更新检索器再切换；不能直接移走旧文件。
4. 动作诡异与复刻：chat_operator 将自动找到的本地立绘和用户上传图混装进 images。
   _generate_image_with_qwen_or_wan 的 1465 行同时要求保留姿态、仅修改明确部分、又绘制全新动作；1469–1470 行也保留未修改部分。

   建议显式保留来源角色：user_edit（只有明确编辑/差分才保留构图）与 local_identity（仅约束外观、新动作场景优先）。
   character_reference_only 现分支硬编码阿米娅，不能直接拿来用于所有游戏人物；需改为动态角色外观。
   游戏画风也应按分类选择，移除每次混合多个游戏画风、强行双人恋爱等无关要求。
   最终请求保留完整的用户任务；必要压缩只压风格套话与重复设定，不能直接截断动作。
   生成响应现在取模型返回 image URL；没有证据证明该代码直接拿本地立绘当生成结果。

只同步蔚蓝档案：`--games ba`。四个既有游戏：`--games ark,wuwa,hsr,ys`。
默认3并发，可指定 `--workers 1` 到 `8`；`--limit 2` 抽样，`--list-only` 只枚举索引。
枚举阶段每5秒提示，传输中显示KB及单文件比例，每完成一项显示总进度；未知 Content-Length 时明确显示总大小未知。
失败重试3次；最终 failed 非零则退出码为1。中断后已验证的文件保留，再运行重新校验；未完成的 .part 文件会重新下载。
